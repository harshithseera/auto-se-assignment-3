# ADR-013: Per-run token budget that rolls back code changes (D9)

## Status

Accepted (2026-11-21). Extends [ADR-009](ADR-009.md). It adds one budget to ADR-009 and supersedes none of it.

## Context

ADR-009 limits each run by call count (retry caps, 2 review rounds), turns per call (`--max-turns`) and time (call and job timeouts). Nothing limits **tokens**, and on a Claude Pro subscription tokens are the scarce resource: running out of them stops every later run that day. The real runs varied widely in token use:

| Run | Builder calls | Output tokens | Input tokens incl. cache |
|---|---|---|---|
| Typical (#16–#20, #34) | 4 | 3,800–8,400 | 160K–240K |
| #33 vague, two fix rounds | 8 | 12,430 | 572,106 |
| #35 `batch()`, one fix round | 6 | 17,820 | 425,737 |

The worst case allowed by ADR-002 and ADR-009 is about 30 builder calls per run, several times the heaviest run we saw. A run that hits a call limit partway through can also leave half-finished code on the branch.

## Decision

We will give each issue run a token budget, summed over every builder call logged in `.autose/issue-N/usage.jsonl` (the build job and the fix job together). The defaults are **40,000 output tokens** and **1,500,000 input tokens including cache**, about 2–2.5× the heaviest real run. A normal run is therefore never cut off, and a runaway run is stopped long before the worst case. The pipeline checks the totals deterministically **before every builder call**. Because the check comes before the call, the overshoot is bounded by one call, which `--max-turns` caps.

When the budget is exceeded:

1. Every file outside `.autose/` is restored to the commit the current pipeline invocation started from. For a fresh run that is `master`. For a fix round it is the PR as reviewed. The pipeline records that commit before stage 1 as its saved state. Files the agent added are removed and files it deleted come back.
2. The pipeline writes `budget.md` with the totals, the limits and the restored commit. Earlier artifacts are kept.
3. It commits and pushes, and comments **"token limit exceeded, code restored"** on the issue, and on the PR if one is open.

The limits, along with `AUTOSE_IMPL_ATTEMPTS` and `AUTOSE_BUILDER_MAX_TURNS`, can be changed through GitHub repository variables without a code change. If a variable is unset, the default in the code applies.

## Consequences

- Each run's cost has a known upper bound, and an overrun never leaves partial code behind for a human to untangle.
- The defaults come from 13 real runs. A much harder issue could be stopped even though it would have succeeded. The fix is to raise the repository variable for that run.
- The reviewer is not covered. It is a single call capped by `--max-turns` (25). Its token use is logged per review but not budgeted.
- The rollback relies on the pipeline being the only writer on `autose/issue-N`, which ADR-005 and ADR-010 already guarantee.
- The defaults have not yet been triggered by a real run. The behaviour is tested locally: a simulated overrun restored a modified, an added and a deleted file, and kept the artifacts. The README describes how to show the path live by setting a low budget.
