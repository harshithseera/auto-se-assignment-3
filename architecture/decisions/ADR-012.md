# ADR-012: Neutral review prompt with a short checklist (D8, supersedes ADR-008)

## Status

Accepted (2026-11-21). Supersedes [ADR-008](ADR-008.md).

## Context

ADR-008 made the reviewer independent in five ways. Two of them were about the prompt: an adversarial stance ("assume at least one defect") and an evidence rule (every finding needs `path:line` plus the command that confirmed it, and an approval needs a five-item checklist). Experiment 2 (`experiment/variants.md`) compared that prompt (`default`) with a neutral prompt that only asks for a `VERDICT:` line (`plain`). Both ran on the seeded PRs, in both rounds, with the same model, tools, permissions and isolation:

| | v1 seeds (#7–#11) | v2 seeds (#21, #24, #26, #27, #31) | Total |
|---|---|---|---|
| Correct verdicts, `default` | 5/5 | 5/5 | 10/10 |
| Correct verdicts, `plain` | 5/5 | 5/5 | 10/10 |
| Output tokens, `default` | 6,012 | 6,071 | 12,083 |
| Output tokens, `plain` | 3,938 | 4,188 | 8,126 (−33%) |

The one hard case was the accidental seed S2a (#22), an incomplete fix that a second drop exposes. **Both** prompts approved it. Only the variant that also saw the implementer's notes caught it. On this data, the adversarial stance and the evidence rule added cost without catching anything more. However, the assignment also requires that anyone can follow a run through its review. With the `plain` output, a reader can't tell what the reviewer actually checked.

## Decision

We will make the default reviewer prompt neutral. It no longer tells the reviewer to assume a defect, and findings no longer need attached evidence. It still asks the reviewer to run the suite and probe the behaviour, and it still ends with a **four-item checklist** and a `VERDICT:` line. An approval without the checklist is still treated as malformed (ADR-007). Everything else from ADR-008 stays the same: a separate read-only job, the issue plus the diff only, `.autose/` deleted, no write tools, and the same model. The ADR-008 prompt is kept as `review_adversarial.md` and can be run with `/autose-review variant=adversarial`, so the comparison can be repeated.

## Consequences

- Review cost should fall by roughly a third, judging from the `plain` runs. The new prompt is neither `plain` nor the old default, so it was validated separately with one run on each of the five v2 seeds (workflow `7fd0104`). It scored **5/5 correct verdicts and named every planted defect**, using 4,356 output tokens against 6,071 for the ADR-008 prompt on the same seeds (−28%). Details are in `results/runs.md`, under "ADR-012 validation".
- Reviews stay readable, because every comment still lists what was checked.
- We lose a safeguard that the data cannot show is useful: 10 seeds with one run per cell is a small sample. If a later seed set shows more missed defects, a new ADR can bring the evidence rule back. The adversarial variant is kept for exactly that.
- The miss that mattered (S2a) points somewhere else entirely: neither prompt thinks about sequences of operations. Prompt strength wasn't the problem. Exploring sequences is a gap in the hidden tests and the seeds, recorded under limitations.
