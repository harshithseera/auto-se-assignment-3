# ADR-001: Split the work across agents (D1)

## Status

Accepted (2026-11-21)

## Context

The workflow must cover six fixed stages (requirements, design, implementation, testing, release, review). Each stage produces an artifact and must pass a check before handing over. The reviewer must be independent of the implementer and must not see its conversation or reasoning. More agents mean more prompts, hand-offs and failure points; fewer agents mean larger contexts and less separation of concerns.

Options available:

- One agent for stages 1–5 plus a separate reviewer agent
- One agent per stage (six agents)
- A planner/orchestrator agent delegating to worker agents

## Decision

We will use two agents. A **builder** agent handles stages 1–5 and a separate **reviewer** agent handles stage 6.

The builder is not one long conversation. The pipeline script starts a fresh `claude -p` call for each stage, with a prompt for that stage. That call reads the earlier artifacts and writes only its own artifact. So the stages stay separate (one prompt, one artifact, one check each) without running five different agent setups. The reviewer is its own agent, with its own prompt, Actions job and permissions, because the assignment requires an independent reviewer.

We chose this over one agent per stage and over a planner with workers because of the constraints we have: one day to build, and the request limits of a Claude Pro subscription. Fewer agent setups mean fewer prompts to debug and fewer hand-offs that can break. A planner would also add an extra LLM call to every stage.

## Consequences

- Only two agent setups to build and debug. Per-stage prompts still give each stage a clean context and its own artifact.
- All builder stages share one model and one style of prompt, so a misreading in `spec.md` can carry through design, code and tests. The independent reviewer and the hidden tests are the guard against that.
- The script, not an agent, keeps the stage boundaries. If an agent writes outside its stage's artifact, the check fails rather than another agent noticing.
- If runs show the builder failing at one stage in particular, that stage can become its own agent in a later ADR that supersedes this one.
