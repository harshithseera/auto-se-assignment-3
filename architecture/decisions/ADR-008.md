# ADR-008: Reviewer independence (D8)

## Status

Superseded by [ADR-012](ADR-012.md) (2026-11-21). Accepted earlier the same day. Points 1, 2 and 5 (separate job, withheld inputs, read-only tools) carry over unchanged. Points 3 and 4 (adversarial stance and evidence rule) are replaced.

## Context

The reviewer may see only the issue, the diff, and the repository at the PR's latest commit. It may run code but not push, and gets its own prompt. LLM reviewers tend to approve plausible-looking changes. The design must stop blanket approval, and five seeded PRs with known defects will measure whether it does.

Options available:

- Separate Actions job with read-only token
- Different model from the implementer
- Adversarial prompt requiring concrete evidence (test runs, cited lines) before approval
- Combination of the above

## Decision

We will make the reviewer independent in five ways:

1. **Separate Actions job.** It runs on a fresh runner with `contents: read`. The workflow-level token used to post comments is held by the script, not the agent.
2. **Withheld inputs.** It gets the issue and the diff, plus the repository at the PR head with `.autose/` deleted. It never sees implementer artifacts or transcripts (ADR-003, ADR-004).
3. **Its own prompt.** The prompt states that the implementer is a different agent whose work is assumed to have at least one defect.
4. **Evidence rule.** The reviewer must run the full test suite. Every finding must cite `file:line` and say how it was confirmed (a test or a `python -c` run). An `approve` verdict must include a checklist of what was checked: each requirement in the issue, whether the tests are meaningful, edge cases, and unrelated changes. An approval without the checklist is treated as malformed.
5. **Read-only tools.** It cannot edit, commit or push (ADR-005).

The review is posted as a PR comment with the verdict, not as a GitHub "Approve" review. The PR was opened by `github-actions[bot]` with the same token, and GitHub does not let an author approve their own PR. In any case, merging is left to a human.

We use the same model as the builder (ADR-006), so independence comes from isolation and the prompt rather than from a different model.

## Consequences

- The reviewer judges the change only against the issue and the code. It cannot be steered by the implementer's explanations.
- The evidence rule makes rubber-stamp approvals visibly incomplete, and it costs more review turns.
- Same-model blind spots remain. The five seeded PRs with known defects measure how many the reviewer catches. The decision experiment compares this reviewer with a variant that does get the implementer's artifacts.
- Assuming a defect exists may push the reviewer to raise false alarms on correct PRs. False positives are counted separately in Results.
