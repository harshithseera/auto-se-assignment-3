# ADR-005: Tools and how each agent gets them (D5)

## Status

Accepted (2026-11-21)

## Context

Agents need to read and edit code, run tests, and interact with GitHub (branches, commits, PRs, comments). The reviewer must be able to read and run code but not push. Issue text is untrusted, so an agent holding a write-capable token can be steered by prompt injection.

Options available:

- Agent CLI/SDK built-in file and shell tools with an allow-list, with git/gh done by the surrounding script
- GitHub MCP server given to the agents
- gh CLI given to the agents
- GitHub REST API calls from the agents

## Decision

We will run both agents with the Claude Code CLI in headless mode (`claude -p`), and limit each one's tools with `--allowedTools`:

- **Builder:** `Read`, `Write`, `Edit`, `Glob`, `Grep`, `Bash(python -m pytest:*)`, `Bash(python -c:*)`.
- **Reviewer:** `Read`, `Glob`, `Grep`, `Bash(python -m pytest:*)`, `Bash(python -c:*)`, with `Write` and `Edit` blocked.
- `WebFetch` and `WebSearch` are blocked for both.

Neither agent can run `git` or `gh`, and neither holds a GitHub token. The Python scripts do everything that touches GitHub: creating branches, committing, pushing, `gh pr create` and `gh pr comment`. The scripts remove `GITHUB_TOKEN` and `GH_TOKEN` from the environment before starting `claude`. `actions/checkout` runs with `persist-credentials: false`, so the token is not left in `.git/config` either.

We chose this over handing the agents the GitHub MCP server or the `gh` CLI because only code we wrote can change GitHub. Even a prompt-injected agent can only edit files in its working copy, and the script decides what of that gets pushed.

## Consequences

- If an agent goes wrong, the damage stays inside the checkout. The push is limited to `autose/*` branches, and `master` is protected.
- Agents cannot look up extra context on GitHub, such as other issues or PR history. The script must put everything an agent needs into its prompt.
- The `Bash(...)` allow-list matches command prefixes. A command it does not cover makes the agent stall rather than fail cleanly, so prompts have to name the exact test command.
- With no write tools, the reviewer cannot write a new test file to check an edge case. It can only run existing tests or `python -c` snippets.
