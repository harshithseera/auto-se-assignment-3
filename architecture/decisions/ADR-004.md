# ADR-004: Where state lives between stages and runs (D4)

## Status

Accepted (2026-11-21)

## Context

Each GitHub Actions job starts on a fresh runner, so nothing persists between jobs or runs unless stored somewhere. Anyone following a run must be able to find its artifacts from GitHub. Runs may be cancelled or restarted. The reviewer checks out the PR head, so anything stored on the branch is visible to it unless removed.

Options available:

- Files committed on the feature branch (e.g. `.autose/issue-N/`)
- PR or issue comments
- Actions artifacts (expire, need download)
- Actions cache

## Decision

We will store all stage artifacts as files in `.autose/issue-N/` on the feature branch `autose/issue-N`. The pipeline commits each artifact when its stage ends, whether the stage passed or failed. The PR description is `pr.md`. Each review is posted as a PR comment and also uploaded as an Actions artifact (`review-1`, `review-2`). The `fix` job downloads it and commits it to the branch as `review.md`.

Jobs pass state through the branch:

- `fix-1` checks out `autose/issue-N` and reads the artifacts already there.
- The review job checks out the same branch and deletes `.autose/` before the reviewer starts (ADR-003).

A new trigger for the same issue starts fresh: the branch is reset to `master` and force-pushed. Earlier attempts stay visible in old Actions runs and PR comments.

We chose branch files because anyone can follow a run by opening the PR's "Files changed" tab, and because files survive job boundaries without expiring the way Actions artifacts and cache do.

## Consequences

- Every run can be read on GitHub: the artifacts, the PR and the review comments.
- Artifacts show up in the PR diff next to the code. A human merging must drop `.autose/` or accept it. We document this in the README.
- The reviewer's view has to be cleaned explicitly. If someone forgets the `rm -rf .autose/` step, reviewer independence silently breaks. This is the decision that ADR-008 depends on most.
- Restarting starts from the beginning instead of resuming. That is simpler and more reliable, but it costs more usage on a restart.
