# ADR-010: Triggers, permissions to start, and concurrency (D10)

## Status

Superseded by [ADR-011](ADR-011.md) (2026-11-21). Accepted earlier the same day.

## Context

The run starts from an issue labeled `autose` or an `/autose` comment on an issue or PR. The fork is public, so anyone can comment, but only collaborators can add labels. Two triggers on the same issue could start overlapping runs that push to the same branch.

Options available:

- Label only
- Label or comment, restricted by `author_association` (OWNER/COLLABORATOR)
- Per-issue `concurrency` group: cancel in-progress vs queue

## Decision

We will start a run on two events:

- `issues: labeled`, when the label is `autose`.
- `issue_comment: created`, when the comment body starts with `/autose`.

A `gate` job lets a comment through only if `author_association` is `OWNER`, `MEMBER` or `COLLABORATOR`. Label triggers are already restricted, because only users with triage access or above can add labels. A `/autose` comment on a PR is mapped to its issue through the branch name `autose/issue-N`, and starts a fresh run for that issue (ADR-004).

Concurrency uses the group `autose-issue-<N>` with `cancel-in-progress: false`. A second trigger for the same issue waits for the running one to finish, and GitHub keeps only the latest waiting run. Different issues run in parallel.

We chose this because the fork is public: anyone can comment, but only maintainers should spend the team's Pro usage or start agents. We queue rather than cancel, so a run is never killed between pushing and reviewing, which would leave a PR with no review.

## Consequences

- Outsiders cannot start runs. Their issue text is still untrusted once a maintainer triggers a run on it (ADR-009).
- Two triggers on one issue never race on the same branch.
- A maintainer who triggers twice by mistake gets a second full run after the first one ends, which uses more Pro quota.
- Issue-comment workflows run from the default branch's workflow file, so workflow changes take effect only once they are on `master`.
