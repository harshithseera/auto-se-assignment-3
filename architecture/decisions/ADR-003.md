# ADR-003: Hand-offs between stages (D3)

## Status

Accepted (2026-11-21)

## Context

Each stage consumes earlier artifacts (`spec.md`, `design.md`, `diff.patch`, `test_report.md`, `pr.md`, `review.md`). Passing everything gives each agent full context but larger prompts and possible anchoring on earlier mistakes. The reviewer may see only the issue, the diff, and the repository at the PR's latest commit.

Options available:

- Full earlier artifacts plus repository access
- Summaries of earlier artifacts
- Only the immediately preceding artifact

## Decision

We will give each builder stage the issue text, **all** earlier artifacts in full (`spec.md`, `design.md`, and so on) and the repository checkout. The `fix` job also gets `review.md`. We will not summarise between stages.

The reviewer gets only:

- the issue title and body
- the diff `master...HEAD`, without `.autose/`
- the repository at the PR's latest commit, with `.autose/` deleted

It never sees `spec.md`, `design.md`, `test_report.md`, `pr.md` or any implementer transcript. Transcripts are never saved as artifacts at all. They appear only in that job's Actions log, which the reviewer cannot read.

Full artifacts are the simplest option and lose no detail. The artifacts in this pipeline are short enough to fit easily in context. The reviewer is held back from the spec on purpose: it reads the issue for itself, so it can catch a spec that misread the issue.

## Consequences

- Builder stages always have the exact acceptance criteria, which the testing stage needs to write one test per criterion.
- Prompts grow with each stage. That is fine at this size, but it would matter for large issues.
- A wrong earlier artifact is passed on in full, and later stages may anchor on it.
- The reviewer may flag something the spec deliberately left out. We accept that cost for a reviewer that judges the work against the issue itself.
