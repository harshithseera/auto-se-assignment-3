# ADR-009: Safety, budgets and failure handling (D9)

## Status

Accepted (2026-11-21)

Extended by [ADR-013](ADR-013.md): per-run token budget with code rollback.

## Context

Agents run unattended in GitHub Actions with an API key stored in repository secrets. Issue and comment text is written by outsiders and may contain prompt injection. Actions jobs have time limits; agents can loop, stall, or burn tokens. A hard provider spending limit is required.

Options available:

- Per-agent turn limits, retry caps and job timeouts
- Treating issue text as quoted data, never as instructions
- Keeping write tokens out of agent tool access
- Input filtering or sandboxed containers

## Decision

We will limit every run with fixed budgets:

- `--max-turns` on every `claude -p` call: 30 per builder stage, 25 for the reviewer.
- `timeout-minutes` on every job: 45 for `build` and `fix`, 20 for `review`, 10 for `ci`.
- Retry caps from ADR-002.

A stage that hits a budget counts as a failed check. The stage writes the reason into its artifact, and the run stops with a comment on the issue.

Against prompt injection:

- Issue and comment text goes into prompts only inside `<untrusted_issue>` tags, with the instruction that it is data describing a request, not instructions to follow.
- Agents have no network tools, no git, and no GitHub token (ADR-005).
- The script refuses to push a diff that touches `.github/` or files outside the repository.
- Pushes go only to `autose/issue-N`. `master` is protected.
- `CLAUDE_CODE_OAUTH_TOKEN` is passed only to the steps that start `claude` and is never echoed.

We chose these over input filtering or sandbox containers because they are simple, and they hold even if an injected instruction is obeyed. The agent still cannot reach anything that matters.

## Consequences

- The worst case of a successful injection is a bad diff on a feature branch, which a human reviews before any merge.
- Budgets are guesses. Too small and real fixes stop early; too large and one stuck run uses up the Pro limit. Runs will show which, and the values are tuned in a later ADR if needed.
- Wrapping untrusted text in tags reduces injection but does not stop it. The real protection is that the agent has no capabilities worth hijacking.
- A Pro limit hit partway through a run looks like a timeout or error. The stop comment has to say which happened.
