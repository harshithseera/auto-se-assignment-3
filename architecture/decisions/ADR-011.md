# ADR-011: Exact command matching and a separate review-only trigger (D10, supersedes ADR-010)

## Status

Accepted (2026-11-21). Supersedes [ADR-010](ADR-010.md).

## Context

ADR-010 started a run on any comment whose body *starts with* `/autose`, and put every run in one concurrency group per issue or PR (`cancel-in-progress: false`). Two things in the real runs showed this was wrong:

1. The experiments needed a way to run only the reviewer on the seeded PRs, so we added `/autose-review [variant=…]`. Because that command also starts with `/autose`, each one started the main `autose` workflow as well. Five runs failed at the `gate` job (listed under "Excluded runs" in `results/runs.md`). They failed only because the seeded branches are not named `autose/issue-N`. On a real autose PR, the same comment would have started a full rebuild.
2. We queued two review variants on the same PR within a few seconds of each other. GitHub keeps only one *pending* run per concurrency group, so the second variant would have cancelled the first. That would silently lose experiment data.

## Decision

We will match commands exactly. The main workflow accepts only a comment that is exactly `/autose`, or `/autose` followed by a space. Review-only runs are a separate workflow, `autose-review.yml`, triggered by `/autose-review`. It applies the same `author_association` check and has **no** concurrency group, because reviews are read-only and can safely run in parallel. The main workflow keeps its per-issue queue from ADR-010, because overlapping builds would race on the same branch. Label triggers are unchanged.

## Consequences

- One comment can no longer start two workflows, and review variants no longer cancel each other.
- Two review-only runs on the same PR can now post their comments in either order. Each comment names its variant and run link, so this does no harm.
- Adding a new command now means writing a new exact match. A prefix check is no longer trusted.
- The lesson: concurrency groups are a design decision, not just setup. They drop work silently instead of failing loudly, so they are hard to spot without a run that exercises them.
